Migrating from manifold3d

ordito.boolean is a port of Manifold's Boolean, and the functions below port its other operations. They are not look-alikes: each runs Manifold's own exact predicates, symbolic perturbation, triangulator and topology cleanup on the GPU, and the test suite compares its output with manifold3d's array for array, so on the same float32 inputs you get the same mesh back: for the Booleans and plane cuts the same vertices and triangles in the same order, and elsewhere the same mesh up to vertex numbering and face order. Like building a Manifold from a Mesh, each function first cleans its input (drops triangles that name a vertex twice, splits pinched vertices, collapses edges shorter than the precision, swaps away degenerate triangles, drops unused vertices), so a raw scan gives the same answer in both.

import manifold3d as m3  # before
import ordito as od  # after

The structural difference: a manifold3d.Manifold is an immutable solid object, built once from a Mesh and evaluated lazily, and its operations are methods and operators (a + b, a - b, a ^ b). ordito has no solid object. Each function takes (vertices, faces) arrays, validates that they form a closed, consistently wound mesh, computes the answer at once and returns new arrays, which are again a valid solid and can be passed straight on.

import manifold3d as m3
import numpy as np
import warp as wp

import ordito as od

# A Manifold from ordito arrays, and back.
vertices, faces = od.creation.icosphere(subdivisions=3)
triangles = faces.numpy().reshape(-1, 3).astype(np.uint32)
solid_m3 = m3.Manifold(m3.Mesh(vert_properties=vertices.numpy(), tri_verts=triangles))
mesh_m3 = solid_m3.to_mesh()
vertices_od = wp.array(np.asarray(mesh_m3.vert_properties)[:, :3], dtype=wp.vec3)
faces_od = wp.array(np.asarray(mesh_m3.tri_verts).ravel(), dtype=wp.int32)
print(od.equality.meshes_allclose(vertices, faces, vertices_od, faces_od))  # True

What's different, not just renamed

  • Validation is eager, and an invalid input raises. Manifold records a bad input in status() and returns an empty solid; ordito raises ValueError naming what is wrong (not closed, an edge shared by more than two faces, inconsistent winding). repair.make_solid turns a broken scan into a valid input.
  • Inputs are welded by index. A manifold3d.Mesh with merge_from_vert / merge_to_vert can describe a solid whose vertices are duplicated along seams; ordito reads the faces' indices as they are, so weld first with repair.remove_duplicated_vertices.
  • No vertex properties or face ids ride along. Manifold carries vert_properties beyond the position and a per-face run_original_id through a Boolean. In ordito a result names its vertices as the inputs' vertices it keeps, then the crossings; to carry colours, UVs or labels through other edits use return_provenance=True where the function offers it.
  • No lazy evaluation. Each call computes its answer before returning, so time a Boolean as it returns rather than after a num_vert() or to_mesh() call that forces Manifold's.
  • collapse_collinear=False keeps the crossing vertices Manifold collapses where flat faces cross along straight lines: the vertex set of an exact-arithmetic Boolean such as libigl's CGAL one (what PyMeshLab's generate_boolean_* filters return). On curved inputs both give the same mesh.

See the Solids and Booleans gallery for worked examples, and the boolean benchmarks for timings against manifold3d, MeshLib, PyMeshLab and trimesh.
